# Data-only factory-reset scope audit

Status: approved implementation boundary (audit gate)
Audited: 2026-08-06
Repositories: `power-monitor` and `power-monitor-sensor`

This matrix is the deletion allow-list for the coordinated data-only reset. Anything not explicitly classified as **Delete**, **Reset**, or **Rebuild** is preserved. Unknown files and rows fail closed and stop the operation; they are never removed by a wildcard fallback.

The reset is site-scoped, uses a durable operation UUID and a monotonically increasing data generation, and records one trusted per-device sequence boundary. The server first creates and verifies a backup unless an administrator separately confirms permanent no-backup execution. Sensor storage is never formatted, PZEM cumulative energy is never reset, credentials/configuration are never erased, and all file deletion is restricted to positively classified reading artifacts.

## Legend and dependency order

- **Delete**: remove rows/files belonging to the selected site and pre-reset generation. A condition in this column is part of the allow-list.
- **Reset**: retain the entity but replace only the named data-history fields or cursor/generation state.
- **Preserve**: immutable identity, configuration, security, recovery, or source evidence retained across reset.
- **Rebuild**: derived state recreated from post-reset data or rematerialized at the reset boundary.
- **B0**: authorize, lock scope, capture plan/configuration digests, and persist operation.
- **B1**: create and independently verify the selected backup; no-backup requires the stronger confirmation path.
- **S1/S2**: sensor prepare/commit. Prepare is reversible; commit authorization is the point of no return.
- **D1..D8**: central cleanup in foreign-key-safe order.
- **R1..R4**: install new generation, pricing boundary, cursors, and invalidate caches.
- **V1**: postconditions and preservation-digest verification before completion.

Backup treatment values mean: **Included** is captured in the default verified backup; **Excluded artifact** is not a database row and must be copied or hashed explicitly if recovery requires it; **Preserved live** remains in place; **No-backup warning** is irrecoverable when the operator selects the permanent option.

## Dependency-safe execution order

1. **B0 — plan and lock:** authorize `system.data_reset`, require recent reauthentication, resolve the site/device UUID scope, calculate exact row/file counts, capture active-pricing and server/sensor keyed configuration digests, persist generation and per-device trusted boundaries, then lock one active operation per site.
2. **B1 — recovery boundary:** create the default database plus artifact manifest backup, restore it into an isolated database, verify required tables and hashes, and record only opaque backup ID/hash. The permanent no-backup branch requires the stronger phrase and audit event.
3. **S1 — prepare:** contact available sensors, authenticate every request, gate reading sync/config/OTA mutations, flush/finalize the current interval, capture card/config/build/boundary evidence, and persist signed prepared receipts. Missing sensors are explicitly deferred or block execution according to the approved plan.
4. **S2 — commit sensors:** persist commit authorization before any irreversible mutation, advance sequence and reading cursors, delete only classified reading artifacts, install the logical energy baseline, verify configuration/card/PZEM preservation, and persist signed completion. Retries resume the recorded checkpoint.
5. **D1 — quiesce copied output:** cancel scoped jobs and stage eligible exports, reports, bill artifacts, and measurement logs in operation quarantine. Restore quarantine on any pre-commit cancellation.
6. **D2 — dependent results:** clear notifications/alerts, cost/tier/projection/rollup results, and bill-extraction children selected by scope.
7. **D3 — usage and intervals:** clear normalized intervals, manual/imported usage, old billing cycles, bill-history links, and selected imports.
8. **D4 — raw history and assignments:** clear old-generation readings; end historical/current rate assignments while retaining the exact active graph for rematerialization.
9. **D5 — device history:** clear gaps and pre-reset measurement heartbeats/status while retaining safe signed liveness evidence.
10. **D6 — dependency-safe pricing/source cleanup:** delete only unreferenced historical versions and artifacts after cross-site/current/future reference checks.
11. **D7 — sanitize retained evidence:** redact measurement/cost values from device events, audit details, notifications, and mixed logs.
12. **D8 — quiesce/revise workers:** remove old-generation work and watermarks so background processing cannot recreate history.
13. **R1 — epoch/cursor boundary:** increment site/device data generation exactly once, install the trusted sequence boundary, and reject/quarantine old-generation or at/below-boundary payloads.
14. **R2 — pricing baseline:** create the clean billing/calculation period at the reset timestamp and attach the exact canonical active pricing configuration with zero accumulated usage/cost.
15. **R3 — finalize files:** commit DB state, purge operation quarantine, and retain backup/recovery metadata. No automatic restore occurs after a partial post-commit failure.
16. **R4/V1 — invalidate and verify:** rotate history revision, invalidate continuations/caches, run deletion and FK/reference checks, compare configuration/pricing digests, verify connected participants, mark disconnected participants pending, and emit the immutable audit result.

## Global postconditions

- No selected-site pre-reset raw, normalized, rollup, cost, tier, usage, bill-derived, report, export, cache, or measurement-log history is accessible from supported APIs or background workers.
- A site reset fails closed when historical device-assignment lineage extends to a sensor now assigned elsewhere. Device-wide local storage has no site epoch, so neither selective deletion nor central-only replay prevention is currently safe.
- Every new reading carries the new data generation and a sequence strictly above the durable trusted boundary. Old-generation, stale-card, replayed, and at/below-boundary payloads receive stable typed rejections and cannot update measurement/status state.
- The current utility account, plan, rate version semantics, tiers, TOU periods, thresholds, baselines, fixed charges, adjustments, and future assignments have the same ordered canonical hash and exact Decimal values as before reset.
- Users, roles, permissions, sessions, MFA, site/device UUIDs, device credentials, network configuration, topology, desired/effective configuration, notifications, firmware/OTA evidence, event history, and coredumps remain intact.
- The sensor SD filesystem is not formatted; card generation is unchanged; PZEM reset is never called; the raw cumulative meter value is preserved; reported logical energy begins at zero and increases from new consumption.
- Duplicate plan/prepare/commit/cancel/status/execute calls are idempotent. Pre-commit cancellation makes no data changes. Power loss or process restart resumes from a durable checkpoint without lowering a cursor or repeating an irreversible step.
- The default backup is verified by hash and isolated restore before commit. The no-backup mode is explicitly audited as irreversible, and the system never claims it can restore that operation.

This document is normative for implementation and tests. Any newly discovered persistence location must be added here and reviewed before reset code may mutate it.
