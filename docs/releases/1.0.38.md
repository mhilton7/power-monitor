# Power Monitor Server 1.0.38

- Server version: `1.0.38`
- Device protocol: `pm-protocol/1.0.0` (unchanged)
- Coordinated data-reset protocol: `data-reset/1.0.0`
- Reset-capable sensor firmware: `1.0.18`

Version 1.0.38 adds the administrator-only **Reset readings and pricing
history** workflow. It coordinates a durable two-phase reset across the server
and every assigned sensor while preserving identity, credentials, network and
hardware configuration, security evidence, and the exact effective pricing
configuration.

The release adds:

- a read-only, expiring reset plan with table-level deletion counts, sensor
  classifications, sequence boundaries, and preserved-pricing digests;
- verified-backup-by-default and separately acknowledged no-backup execution;
- durable generation and sequence-boundary ingestion gates for push and pull;
- fail-closed generation and sequence-boundary handoff for reset-capable fresh
  enrollment, installed durably before credentials become active or any first
  heartbeat/upload can run;
- authenticated prepare, commit, status, and cancel checkpoints with keyed
  receipts and configuration-preservation evidence;
- sensor-side fail-closed NVS capacity admission for the complete transactional
  reset journal and preserved enrollment/configuration state, including
  terminal journal compaction and repeated-reset admission credit;
- dependency-safe measurement, cost, tier, pricing-provenance, report, export,
  and measurement-bearing log cleanup;
- clean billing-cycle and pricing baselines at the reset timestamp; and
- restart-safe retry, cancellation, reconnect, and filesystem-quarantine
  recovery.

Database migration `20260806_0031` must be applied before the API and worker
are upgraded. Sensor firmware 1.0.18 must be installed on connected sensors to
participate immediately; older active sensors remain ingestion-gated and
pending until a reset-capable firmware reports on authenticated reconnect.
The migration also widens reading, heartbeat, gap, and event protocol sequence
columns from PostgreSQL `INTEGER` to `BIGINT`; schedule the migration with the
normal maintenance safeguards for large populated history tables.

Do not publish 1.0.38 container artifacts or promote sensor 1.0.18 solely from
this source note. Complete the validation matrix, record immutable artifact
digests, and perform the documented physical canary before deployment.

## Repeat-reset capacity resolution

Sensor 1.0.18 replaces both atomic copies of completed event, cleanup, and
drain journals with compact tombstones. A later prepare credits only active,
semantically validated terminal slot allocations already included in the
worst-case live-set reservation. Credit is capped so the partition always
retains a complete 126-entry NVS garbage-collection page and a 32-entry
rewrite margin. Exact/below admission, maximum tombstone, two-copy compaction,
and credit-floor cases pass in both native reliability builds. Physical
two-reset validation on a realistically populated enrolled device remains in
the canary procedure and is not claimed by this source release.
