## Included changes

- Exact PostgreSQL History aggregation and pagination avoid hydrating the
  unbounded raw-reading set while preserving Decimal rate and tier results.
- History measurement and pricing queries share a repeatable-read snapshot,
  with a bounded auxiliary connection and a serial fallback under pool
  pressure.
- The browser History client coalesces refreshes, cancels superseded requests,
  and keeps large accessible tables out of the DOM until requested.
- Firmware deployment transitions are centralized, idempotent, and reconciled
  by the worker rather than relying on an administrator opening the page.
- OTA evidence ordering rejects stale reports and preserves authenticated,
  monotonic progress for each deployment attempt.
- The release workflow binds dependency audits, migration evidence, source
  commit, toolchain versions, and image metadata before publication.

## Deployment and rollback

Do not publish the API, frontend, or backup images under version `1.0.30`.
For the superseding release, publish all application images under its single
version, record their immutable digests, then render and validate the TrueNAS
YAML. The PostgreSQL host path remains exactly:

```yaml
volumes:
  - /mnt/Apps/Power/postgres:/var/lib/postgresql/data
```

Before upgrade, create the verified logical backup and TrueNAS ZFS snapshot
described in the deployment documentation. Rollback restores the prior
digest-pinned application images; if database rollback is required, restore
the pre-upgrade logical backup or ZFS snapshot using the documented procedure.
